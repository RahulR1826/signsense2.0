# Research notes — product feasibility (2026-10-12)

Question from user: how does the model work for end users in a call, what do they download, what if they have no GPU, and is this a reliable, sellable product?

## What a user's browser downloads (first visit, then cached)
| Asset | Size (uncompressed) |
|---|---|
| MediaPipe vision WASM (SIMD build; only one variant is loaded) | ~11.8 MB |
| Hand landmarker (f16) | 7.8 MB |
| Pose landmarker lite (f16) | 5.8 MB |
| Face landmarker (f16) | 3.8 MB |
| Our sign classifier (ONNX, expected) | ~1–5 MB |
| ONNX Runtime Web WASM (one variant) | ~10–25 MB (npm package is 145 MB unpacked, but a browser loads one build) |
Total ≈ 40–55 MB once; cache it (service worker / PWA). No install needed.

Only the **signer's** device runs sign recognition. The hearing person's device only shows text, speaks it (TTS) and plays sign clips — no heavy ML.

## "No GPU"
Browser "GPU" = WebGL/WebGPU on any GPU, including integrated Intel/AMD/phone GPUs. Truly weak devices fall back to WASM-on-CPU. No good public benchmark exists for current MediaPipe Tasks on low-end CPUs → must measure ourselves. Our first measurement: 7.7 FPS (hand+pose+face, GPU delegate) on the dev laptop — too slow, cause not yet known.

## Prior art / competitors
- Google Research 2020: in-browser *sign language detection* (is someone signing?) for video calls, pose-based, <4 ms classifier — research demo, not a shipped Meet feature. https://research.google/blog/developing-real-time-automatic-sign-language-detection-for-video-conferencing/
- Google SignGemma (announced May 2025): sign→text, ASL-focused; not publicly available as of late 2025. Not ISL.
- AI4Bharat OpenHands (ACL 2022): pose-based ISL recognition, pretrained checkpoints, code Apache-2.0, last updated 2023. https://github.com/AI4Bharat/OpenHands
- INCLUDE paper: 94.5% on INCLUDE-50, 85.6% on full INCLUDE (in-dataset test, not real-world).
- Indian products: SignAble (human interpreters on demand), Ishaara (text→ISL avatar; sign→text is a prototype), LetsTalkSign (conferencing with avatar). No product found doing real-time ISL sign→text inside a video call.

## Licences

- ISLRTC dictionary videos: not cleared for reuse in a commercial product → record our own sign clips with Deaf signers.

## Conclusions
1. Sign recognition must degrade gracefully: device check on first run → full / lite / off. Everything except sign→text (calls, captions, text→sign, picture board) works on any device.
2. Reliability for real users comes from **personalisation**: the signer records a few takes of their own signs at setup; adapt the model in the browser. Also covers family "home signs".
3. Lab accuracy ≠ real-world accuracy: always confirm before sending, limited vocabulary, honest confidence.
